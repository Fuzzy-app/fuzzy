# ライブラリ走査の除外ルール

最終更新: 2026-07-28

Fuzzyは保存ルートを走査する際、授業資料ではないことを高い確度で判断できる開発環境、依存パッケージ、キャッシュ、ビルド生成物、VCS・OS内部領域を再帰探索しない。利用者の資料ファイル自体は移動・削除・改名しない。

## 基本方針

- `.py`、`.json`、`.ipynb`、設定ファイル、拡張子なし、実行ファイルを、ファイル名や拡張子だけでは除外しない
- PDF、Office、ソース、データ、アーカイブ、バイナリ等、除外フォルダー外のファイルはBLAKE3とSimHashを計算してSQLiteへ登録する
- 全文索引は本文抽出に対応した形式だけに作成する。バイナリはハッシュ登録までとし、内容をテキストとして解釈しない
- シンボリックリンクとWindowsジャンクションは追跡しない
- FuzzyのZIP検証用一時領域は走査しない
- `.gitignore`は除外設定として使用しない
- `.fuzzyignore`ファイルを自動作成しない
- 利用者指定の除外設定はSQLiteを正本とし、拡張機能の既存「保存・整理設定」ページから編集する。詳細は専用Issueで実装する

## 構造を確認して除外するフォルダー

一般的な名前を持つフォルダーは、プロジェクト定義や環境マーカーを同時に確認してから除外する。

### Python仮想環境

フォルダー名にかかわらず、次のいずれかを満たすフォルダーを除外する。

```text
pyvenv.cfg + Lib/site-packages
pyvenv.cfg + Scripts/python.exe
pyvenv.cfg + bin/python
conda-meta
```

### Rust・Maven

直下に`Cargo.toml`または`pom.xml`があるプロジェクトの`target`を除外する。

### Gradle・CMake

直下に`build.gradle`、`build.gradle.kts`、`CMakeLists.txt`のいずれかがあるプロジェクトの`build`を除外する。

### .NET

保存ルートまでの祖先に`.csproj`、`.fsproj`、`.vbproj`がある場合、`bin`と`obj`を除外する。

### Go・Ruby・PHP

直下に`go.mod`、`Gemfile`、`composer.json`のいずれかがあるプロジェクトの`vendor`を除外する。

### Swift・Xcode

直下に`Package.swift`があるプロジェクトの`.build`、直下に`Podfile`があるプロジェクトの`Pods`を除外する。

## 除外設定の将来拡張

利用者指定の除外設定は、ファイルを作成せずSQLiteへ保存する。

- 保存ルート基準の相対フォルダーだけを受け付ける
- 絶対パス、`.`、`..`、保存ルート自体の除外を拒否する
- 保存ルート全体またはコース単位で設定できる
- 既存の「保存・整理設定」ページ内に追加し、新しい設定画面は作らない
- 設定変更後は影響するコースだけを差分確認する
- 既に登録済みのファイルを物理削除せず、SQLite上で除外状態として保持する
- 除外状態のファイルは通常表示、全文検索、ルール違反、重複候補から外す
- 除外解除時はサイズ・更新日時を比較し、必要なファイルだけ再ハッシュ・再索引する
