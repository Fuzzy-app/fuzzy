# Fuzzy UIデザインシステム

最終更新: 2026-07-29

## 1. デザイン原則

Fuzzyの名称は「曖昧なものを管理する」に由来する。公式アイコンは、紫・青・ミント・オレンジのぼやけた粒子が白い`F`へまとまることで、散らばった情報を一つの明確な整理状態へ統一する意図を表す。

- 多色とぼかしは、ブランド表現、背景の雰囲気、主要導線に限定する
- 成功・警告・エラーなど、意味を持つ状態色へブランド色を流用しない
- 情報量の多い本文は白〜薄い無彩色を基本にし、読みやすさと状態判別を優先する
- 画面は「読み込み中」「利用可能」「空」「成功」「注意」「失敗」の主状態を1つにまとめ、複数の矛盾したメッセージを同時に出さない
- ぼかしは「曖昧な入力」、輪郭のはっきりしたカードと文字は「整理された結果」を表す

## 2. 実装上の正本

色・影・フォントの正本は [`packages/shared/src/styles/theme.css`](../packages/shared/src/styles/theme.css) とする。extension、desktop、siteはこのファイルを読み込み、アプリ固有CSSに色リテラルを追加しない。

新しい色が必要な場合は、用途が既存tokenと異なることを確認してから共通themeへ追加する。コンポーネント名ではなく、`primary`、`surface`、`warning`のような再利用可能な役割で命名する。SVG内の作品固有色、HTMLの`theme-color`などCSS変数を使えない境界は例外とし、公式ブランド色と一致させる。

主要tokenの用途は次のとおり。

| token | 用途 |
|---|---|
| `--fuzzy-brand-gradient` | 主要CTA、ブランドを示す短いアクセント |
| `--fuzzy-brand-atmosphere` | ページ背景の淡い多色表現 |
| `--fuzzy-color-primary` | 選択状態、フォーカス、主要操作 |
| `--fuzzy-color-surface*` | カード、ダイアログ、半透明面 |
| `--fuzzy-color-text*` | 文字の情報階層 |
| `--fuzzy-color-success/info/warning/danger*` | 意味が固定された状態表示 |

## 3. 状態表示

非同期画面の表示判断には`@fuzzy/shared`の`PresentationState`を使う。通信例外の生メッセージを主表示へ出さず、利用者向けの`title`と影響範囲の`impact`を設定する。調査に必要な詳細だけを`technicalDetails`へ保持する。

`tone`の使い分け:

- `loading`: 結果を待っている
- `ready`: 操作可能な通常状態
- `empty`: 正常だが対象がない
- `success`: 利用者操作が完了した
- `warning`: 一部確認や修正が必要
- `error`: 主目的を完了できない

画面固有のbooleanを増やす前に、`PresentationState`または識別可能なunionで表せないか確認する。

## 4. 再利用とレビュー

- DOMへ外部データを入れるときは`textContent`を使い、HTML文字列へ混ぜない
- 画面のデータ取得、状態判定、DOM構築、スタイル注入を同じファイルへ集約しない
- 同じラベル変換・日付整形・エラー文言を複製せず、presentationまたはmodelモジュールへ置く
- UI変更時はライト背景・キーボードフォーカス・エラー／空状態・狭い画面を確認する
- コードレビューでは色リテラル、状態booleanの組み合わせ、巨大な画面controllerの再発を確認する
