# 開発環境セットアップ（Windows 11）

Fuzzy は Windows 11 専用アプリです。このドキュメントでは、開発に必要なツール（Bun / Rust / Tauri 前提パッケージ）のインストール方法と、リポジトリの初回セットアップ手順をまとめます。

---

## 1. Bun のインストール

PowerShell を開いて以下を実行する。

```powershell
powershell -c "irm bun.sh/install.ps1|iex"
```

確認：

```powershell
bun --version
```

`bun: コマンドが見つかりません` のようなエラーが出る場合は、ターミナルを開き直してください。

他の方法（任意）：`npm install -g bun` / `scoop install bun`

参考：[Bun公式インストールガイド](https://bun.com/docs/installation)

---

## 2. Rust のインストール（rustup）

以下のいずれかの方法でインストールする。

**方法A：winget**

```powershell
winget install -e --id Rustlang.Rustup
```

**方法B：公式インストーラー**

[rustup.rs](https://rustup.rs/) から `rustup-init.exe` をダウンロードして実行する。

インストール中、`default host triple` が `x86_64-pc-windows-msvc`（MSVCツールチェーン）になっていることを確認する。すでにRustが入っている場合は、念のため以下を実行しておく。

```powershell
rustup default stable-msvc
```

確認：

```powershell
rustc --version
cargo --version
```

**インストール・切り替え後はターミナル（場合によってはPC）を再起動すること。**

参考：[rustup公式](https://rust-lang.github.io/rustup/installation/windows-msvc.html)

---

## 3. Tauri の前提パッケージ（Windows）

Tauri は Windows 上での開発に **Microsoft C++ Build Tools** と **WebView2** を必要とする。

### 3.1 Microsoft C++ Build Tools

1. [Microsoft C++ Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/) をダウンロードして実行
2. インストール時に **「C++ によるデスクトップ開発」** ワークロードにチェックを入れる

### 3.2 WebView2 ランタイム

Windows 10（バージョン1803以降）・Windows 11には標準搭載済みのため、通常は追加作業不要。万が一入っていない場合は [WebView2 Runtime ダウンロードページ](https://developer.microsoft.com/en-us/microsoft-edge/webview2/#download-section)から「Evergreen Bootstrapper」を入手してインストールする。

### 3.3 VBSCRIPT（MSIインストーラーを作る場合のみ）

`tauri.conf.json` で `msi` ターゲットのビルドを行う場合のみ必要。`failed to run light.exe` のようなエラーが出た場合に確認する。

設定 → アプリ → オプション機能 → Windows のその他の機能 → **VBSCRIPT** が有効になっているか確認する。

参考：[Tauri公式 Prerequisites（Windows）](https://v2.tauri.app/start/prerequisites/)

## 4. VS Code

`.vscode/extensions.json` に推奨拡張機能が定義されているため、VS Codeでリポジトリを開くと自動でインストールが提案される。インデントは **タブ**、改行コードは **LF** に統一されているので、エディタ側の自動整形設定を上書きしないよう注意する（`.editorconfig` / `.vscode/settings.json` が自動適用される）。

---

## 5. リポジトリのセットアップ

1. リポジトリを clone する
2. ルートで依存をインストール：`bun install`
	- パッケージ管理は **bun に統一**（ロックファイルは `bun.lock`。npm/yarn での install は行わない）
	- 初回は postinstall（`wxt prepare` による型生成）が実行される（ルート `package.json` の `trustedDependencies` で許可済み）
3. Rust側のビルド確認：`cargo build`（ルートのCargoワークスペースが `crates/engine-core`・`apps/native-host`・`apps/desktop/src-tauri` をまとめてビルドする）
4. Rust API DTOを変更した場合は共有TypeScript型を再生成：`bun run generate:types`（`packages/shared/src/generated/`は手編集しない）
5. 整形・型チェック：`bun run check` / `bun run build`

※各アプリ・クレートは生成・実装済みのため、`bun create` / `cargo new` による生成作業は不要。`apps/desktop/src-tauri` と `apps/native-host` は共通の`crates/engine-core`へ依存している。

## 6. 一般利用者向けインストール

正式公開版と公開審査前QA版を区別した利用者向け手順は、[`docs/公開ガイド/一般利用者向けインストール.md`](公開ガイド/一般利用者向けインストール.md)を正とする。この章は開発環境から配布成果物を確認する場合の補足として扱う。

一般利用者は開発ツールやターミナルを使用しない。配布フォルダー内の`Fuzzy-Setup.exe`をダブルクリックし、インストーラーとFuzzyの画面案内だけでセットアップを完了する。

SQLiteの利用データは通常`%LOCALAPPDATA%\Fuzzy\fuzzy.db`へ保存する。旧版の`%APPDATA%\Fuzzy\fuzzy.db`は移行せず参照しない。旧世代のSQLiteが見つかった場合は画面から内部データを初期化し、保存済みの授業資料は変更しない。

1. `Fuzzy-Setup.exe`を実行して、現在のWindowsユーザーへFuzzyをインストールする（管理者権限は不要）
2. Fuzzyを起動し、保存先・既存構成・初期ルールを画面上で選ぶ。フォルダー名は日本語名または英語名から選択できる
3. Fuzzyまたは公式サイトの案内から公式ブラウザストアのFuzzy詳細ページを開き、表示された権限を確認して追加する
4. Moodleを開き、Fuzzy画面が拡張機能の実応答を確認して完了表示になることを確認する

native-hostの配置、Native Messagingマニフェストの生成、Chrome・Chromium・Edgeのユーザー単位レジストリ登録はインストーラーとFuzzy本体が自動で行う。アンインストール時はWindowsの「設定 → アプリ → インストールされているアプリ」からFuzzyを削除すると、登録・マニフェストとFuzzy管理下の設定・SQLite・検索索引・表示キャッシュが削除される。利用者が保存した授業資料と書き出したバックアップは削除されず、完了後にPCの再起動も要求しない。拡張機能の追加だけは権限確認を伴うため、ブラウザ上のユーザー操作を必須とし、サイレントインストールしない。

### 公開審査前のQAテスト

公式ストアURLが未設定のローカルテスト版だけは、Fuzzy画面の「拡張機能のフォルダーを表示」から拡張機能の場所を開く。ブラウザの拡張機能管理画面でデベロッパーモードを有効にし、「パッケージ化されていない拡張機能を読み込む」で表示された`chrome-mv3`フォルダーを選ぶ。この操作にもビルドやターミナルは不要だが、公開版ではアプリ内の拡張機能フォルダーを使わず、公式ストアから通常の拡張機能として追加する。

初期設定の保存後、選択した保存先にある既存資料はその場でSQLiteと全文検索索引へ登録される。資料ファイル自体は移動・削除しない。セットアップ後のFuzzy画面では、明示操作による再スキャン・検索索引再構築と、OSのファイルダイアログを使ったバックアップの書き出し・復元を行える。復元時は確認ダイアログを表示し、書き出しでは既存ファイルを上書きしないため、これらの保守にもターミナルは不要である。

SQLite正本または検索索引が破損していてもFuzzyは復旧画面を起動する。SQLiteバックアップがあれば画面から選択して復元でき、同じ起動中のアプリで通常操作へ戻る。バックアップがない場合は、確認後に開けないDBと付随ファイルを別名の復旧用フォルダーへ保全してから新しいDBを作成できる。保全に失敗した場合は新規作成せず、元のDBを維持する。検索索引だけを開けない場合はSQLite正本を基に内部索引を再生成する。いずれも授業資料を移動・削除しない。

配布成果物の`QA-確認用/Fuzzy-Portable`はインストーラーを使わない実機確認用であり、通常利用とアンインストール確認には最上位の`Fuzzy-Setup.exe`を使う。`QA-確認用/Fuzzy-Extension.zip`と`QA-確認用/FuzzyNativeHost.exe`は拡張機能ストア提出・内部結合確認用で、一般利用者が開いたり展開したりする必要はない。

現在のローカルテスト成果物はコード署名証明書を設定していないため未署名である。一般公開前にWindowsコード署名を行うこと。証明書と署名サービスは外部の配布資格情報であり、利用者にコマンド操作を要求するものではない。

## 7. 開発・結合動作確認

- **初期セットアップアプリ（Tauri）**：`apps/desktop` 内で `bun run tauri dev`を実行する。起動前に拡張機能とデバッグ版native-hostが自動ビルドされ、Tauri起動時にNative Messaging登録も自動で作成される
- **Windows配布一式**：リポジトリルートで`bun run dist:windows`を実行する。一般向けのNSISインストーラー・README・SHA-256一覧を`dist/Fuzzy-<version>-windows/`直下へ、ポータブル版・native-host・拡張機能ZIPをその中の`QA-確認用/`へ分離して集約する
- **拡張機能**：Tauriの拡張機能導入画面で「拡張機能のフォルダーを表示」を押し、表示されたフォルダーをブラウザの拡張機能管理画面から読み込む。Chrome・Chromium系は検索バーで`chrome://extensions/`、Edgeは`edge://extensions/`を開き、デベロッパーモードを有効にして`manifest.json`があるフォルダーを「パッケージ化されていない拡張機能を読み込む」から選ぶ
- **完了確認**：拡張機能のインストール・更新・ブラウザ起動時に加え、MoodleページのContent Script起動時にもbackgroundから`reportExtensionRuntime`が送信され、native-hostがSQLiteへ受信日時とバージョンを保存する。Tauriは今回の起動後に届いた互換性のある応答を確認すると自動的に完了表示へ切り替わる。チェックボックスやlocalStorageの完了値は使用しない
- **セットアップ後の再確認**：Tauriを再起動するとSQLiteにあるインストール識別子ごとの最新応答日時とバージョンを確認する。応答履歴がなければ初回導入の応答待機を続け、最終応答が24時間より古い場合は「Moodleを開いて再確認」を押して安定URLからMoodleを開き、新しい応答を待つ。応答がない、拡張機能バージョンが`0.1.0`未満、または通信仕様が不一致の場合は、同じ画面から拡張機能のフォルダーまたは公式配布ページの導入手順を開いて更新・再追加する
- **資料・索引の復旧**：セットアップ後の画面で「保存先を再スキャンして検索索引を再構築」を押す。保存処理との競合を避けるため、資料の保存完了を確認してブラウザを閉じてから実行する。保存済み資料の移動・削除は行わない
- **バックアップ**：同じ画面の「バックアップを書き出す」「バックアップから復元」を使用する。保存先・復元元はOSダイアログで選び、復元前には確認ダイアログが表示される。既存バックアップへの上書きは行わない
- **別PCへの復元**：復元後に以前の保存先が見つからない場合は、同じ画面の「保存先を変更」から現在のPC上の保存フォルダーを選ぶ。既存ルールは保持され、資料ファイルを移動・削除せずにSQLite上の登録先と検索索引だけを再構築する
- **起動時のデータ復旧**：SQLiteを開けない場合は起動直後の復旧画面からバックアップを選ぶ。バックアップがなければ、確認内容と保全先を理解したうえで「破損DBを保全して新しく開始」を押す。検索索引だけのエラーでは「検索索引を再構築」を押す。コマンド操作は不要
- **DBパスの開発用上書き**：分離したテストDBが必要な場合だけ`FUZZY_DB_PATH`を指定する。未指定時は`LOCALAPPDATA`配下を既定とし、旧`APPDATA`側は参照しない

同梱拡張機能の固定ID、許可する将来のストア版ID、公式ストア詳細URLは`apps/desktop/distribution.config.json`で管理する。公開前の`extensionStoreUrl`は`null`とし、ストア審査で確定したIDを`extensionIds`へ追加したうえで、そのIDで終わるHTTPSの詳細URLだけを設定する。ビルド時に生成manifestの公開鍵からIDを再計算し、Native Messagingの`allowed_origins`および`NativeApiClient`のホスト名と一致しなければ配布ビルドを停止する。ワイルドカードや無関係な拡張機能IDは追加しない。

## 8. トラブルシューティング

| 症状                                | 対処                                      |
|-----------------------------------|-----------------------------------------|
| `bun` コマンドが見つからない                 | ターミナル再起動／PATH確認（1章参照）                   |
| `cargo build` が C++ 関連のエラーで失敗する   | Build Tools の「C++ によるデスクトップ開発」が入っているか確認 |
| Tauriアプリ起動時にWebView関連のエラー         | WebView2 Runtimeが入っているか確認（3.2章）         |
| 拡張機能を読み込んでも初期セットアップが完了しない | Fuzzyの「自動修復を再実行」を押し、ブラウザとMoodleを開き直す。配布テストでは生成manifestの固定ID検証結果も確認する |
| SQLiteまたは検索索引を開けない | 起動時の復旧画面からバックアップ復元、DB保全後の新規作成、または検索索引再構築を選ぶ。復旧用フォルダーは削除しない |
| MSIビルドで `failed to run light.exe` | VBSCRIPT機能が有効か確認（3.3章）                  |

困った場合は [Tauri公式トラブルシューティング](https://v2.tauri.app/develop/debug/) も参照する。
