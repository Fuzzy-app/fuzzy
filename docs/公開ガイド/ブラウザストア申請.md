# ブラウザストア申請

## 対応範囲

初回公開は次を正式対象とします。

- Windows 11
- Google Chrome
- Microsoft Edge
- `https://*.wakayama-u.ac.jp/*`の対応Moodle

Firefox、他大学Moodle、すべてのChromiumブラウザでの動作を、未検証のまま掲載しません。対応範囲を広げる場合は、Native Messaging登録、manifest、Moodle DOM解析、QAを追加します。

## 提出物

- 拡張機能ZIP: `dist/Fuzzy-<version>-windows/QA-確認用/Fuzzy-Extension.zip`
- 署名済みWindowsインストーラーの審査用URL
- 公開済みプライバシーポリシーURL
- サポートURLと連絡先
- ストア説明文
- 権限ごとの利用理由
- スクリーンショット
- プロモーション画像
- 審査用Moodleアカウントとテスト手順

ZIPのルート直下に`manifest.json`が必要です。`target`、ソースマップ、秘密鍵、テストデータ、大学の実データを含めません。

## Chrome Web Storeの初回ID確定

QA用manifestには、unpacked環境でIDを固定する公開鍵があります。QA用IDをChrome Web Storeの正式IDと仮定してはいけません。

1. Chrome Web Store Developer Dashboardで`Add new item`を選ぶ
2. 提出ZIPをアップロードするが、公開はしない
3. `Package`からItem IDと公開鍵を確認する
4. ストア公開鍵を`apps/extension/wxt.config.ts`へ反映する
5. 導出されたIDとItem IDが一致することを確認する
6. IDを`apps/desktop/distribution.config.json`の`extensionIds`へ設定する
7. 実在する詳細URLを`extensionStoreUrl`へ設定する
8. 配布ビルドを再実行し、ID検証が成功することを確認する

初回リリース前であれば、従来のQA用IDを正式IDへ置き換える方が構成を単純化できます。既に別IDのテスターがいる場合は、必要な期間だけ両IDを許可し、不要なIDを恒久的に残しません。

秘密鍵をソースコード、GitHub Actions artifact、Issue、PR、GitHub Releaseへ保存してはいけません。Verified CRX Uploadsを使う場合も、秘密鍵は署名サービスまたは安全なキーストアへ保存します。

## Edge Add-ons

1. Microsoft Partner Centerで開発者登録を完了する
2. Chrome互換ZIPを新規拡張機能としてアップロードする
3. Edge側の正式IDを取得する
4. Chrome IDとEdge IDを`extensionIds`へ登録する
5. Native Messaging manifestの`allowed_origins`に双方が含まれることを確認する
6. Edge用の詳細URLを公開サイトへ掲載する
7. Edgeで新規インストール、更新、削除を独立してQAする

Chrome Web StoreとEdge Add-onsでIDが異なることを前提にします。

## 単一目的の説明

推奨する単一目的:

> 和歌山大学の対応Moodleで、授業資料の保存・検索と課題・締切の確認を、利用者のWindows PC内で一元化する。

保存、検索、期限、通知、ルール、重複確認は、この目的の補助機能として説明します。「あらゆるMoodleに対応」「自動で完全整理」など、現在の実装を超える表現を使いません。

## 権限理由

| 権限 | 申請時の説明 |
|---|---|
| `https://*.wakayama-u.ac.jp/*` | 対応Moodle画面からコース、課題、資料候補を読み取り、利用者が選択した資料だけを同一オリジンから取得する |
| `nativeMessaging` | 同じPCにインストールされたFuzzyへ取得済み資料と操作要求を渡し、ローカルSQLite、検索、保存を利用する |
| `storage` | パネル状態、直近の保存先、ランダムなインストール識別子、通知処理状態、実データ由来の表示キャッシュをブラウザ内へ保存する |
| `alarms` | 利用者が有効にした締切確認を端末内で定期実行する |
| `notifications` | 利用者が有効にした締切通知をブラウザへ表示する |

将来使うかもしれない権限を先に追加しません。`<all_urls>`、`cookies`、`tabs`、`downloads`などを機能なしで追加しません。

## プライバシー申告

ローカル処理だけでも、Webページ内容、URL、課題、資料内容、識別子を扱うことを申告します。

- 取り扱うデータ
- 利用目的
- ローカル保存場所
- 外部送信を行わないこと
- 第三者提供・広告・解析を行わないこと
- 保持期間
- 利用者による削除方法
- Native Messagingで同じPC内のプロセスへ渡すこと
- Cookieや認証情報をnative-hostへ渡さないこと

ストアDashboardの申告、公開ページ、拡張機能の実装を一致させます。公開主体名、サポートメール、最終更新日も掲載します。

## ストア素材

少なくとも次を準備します。

- 128×128アイコン
- 1280×800または640×400の実画面スクリーンショット
- 440×280の小プロモーション画像
- 必要に応じて1400×560のマーキー画像
- 日本語の短い説明
- 機能一覧、対応環境、対象Moodleを含む詳細説明
- ホームページURL
- プライバシーポリシーURL
- サポートURL

スクリーンショットへ実在する氏名、学生番号、課題内容、認証情報を含めません。サンプルデータまたは審査用データを使用します。

## 審査用手順

主要機能が認証後のMoodleにあるため、審査担当者が再現できる環境を必須とします。

1. 署名済みWindowsインストーラーを取得する
2. Fuzzyをインストールして初期保存先を設定する
3. 提出中の拡張機能を追加する
4. 審査専用Moodleへログインする
5. 指定コースを開く
6. 課題同期、資料保存、検索、締切表示、通知設定を確認する
7. Fuzzy画面でnative-hostの実応答を確認する

個人の大学アカウントを渡しません。認証情報はストアの非公開テスト欄だけへ入力し、リポジトリ、公開文書、Issueへ記載しません。

## 公開範囲

推奨順:

1. Privateで審査と限定テスト
2. UnlistedでURLを知る対象学生へ拡大
3. 対象、サポート体制、安定性が確認できたらPublic

Publicの場合は、和歌山大学Moodleの利用者向けであることをタイトル直下と説明冒頭で明示します。公開範囲にかかわらずストアポリシー審査は必要です。

## 更新

- manifestの`version`を必ず増加させる
- 拡張機能、native-host、デスクトップの互換性を確認する
- Native Messaging契約を破壊的変更した場合はprotocol versionを更新する
- 新しい権限や対応サイトは、コードと同時にストア申告とプライバシーポリシーへ追加する
- 審査承認前に公開版WindowsアプリのストアURLを先行して壊さない
