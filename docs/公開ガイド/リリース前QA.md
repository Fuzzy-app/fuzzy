# リリース前QA

## 目的

このチェックリストは、開発PCでテストが通ることだけでなく、一般利用者がクリーンなWindows 11環境でコマンドなしに導入・利用・復旧・削除できることを確認します。

必須項目に失敗が1件でもある場合は公開せず、Issueと別ブランチを作成して修正します。

## テスト環境

最低限、次を分離して確認します。

| 環境 | ブラウザ | Windowsユーザー |
|---|---|---|
| A | Google Chrome安定版 | Fuzzy未導入の標準ユーザー |
| B | Microsoft Edge安定版 | Fuzzy未導入の標準ユーザー |
| C | ChromeとEdgeの両方 | 既存データを持つ更新ユーザー |
| D | 審査環境相当 | 審査専用Moodleアカウント |

可能なら仮想マシンのスナップショットを使い、過去のNative Messaging登録や開発用拡張機能が残っていない状態から開始します。

## 成果物の同一性

- [ ] mainの対象コミットが明確
- [ ] version、tag、manifest、Tauri、Rust crateが一致
- [ ] `bun run verify`成功
- [ ] Windows正式配布ビルド成功
- [ ] GitHub Actionsの全必須check成功
- [ ] `SHA256SUMS.txt`全件一致
- [ ] 配布物と署名対象のハッシュを記録
- [ ] ストア提出ZIPと審査用Windows版のprotocol versionが一致
- [ ] 3つのEXEの署名が有効

## 証跡

リリース判定には次を残します。

- 対象コミットSHA
- CI URL
- Windows build workflow URL
- ストア提出バージョン
- Chrome／Edge Item ID
- 署名検証結果
- SHA-256一覧
- QA実施日、OS build、ブラウザversion
- 失敗と再確認の記録
- Go/No-Go承認者

認証情報、個人情報、授業資料を証跡へ含めません。
